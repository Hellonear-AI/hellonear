# CLAUDE.md — apps/docs

The docs site, **docs.hellonear.xyz**, a **Mintlify** project (Starter plan) connected to this repository. Moved from a Next.js app to Mintlify on 13 Nov 2026; the Trust Center moved out to `apps/trust` at the same time. Owner: Axel. Root rules in `/CLAUDE.md` also apply.

**Update this file in the same PR whenever you change pages, navigation, the Mintlify settings or where it is deployed.**

## How it works

- **Pages:** one `.mdx` file per page in this folder (frontmatter `title`, `description`), `index.mdx` is the introduction. Most text was sliced from `README.md` and `docs/api-contract.md` §3 on 13 Nov; it does not update by itself, so change the page when the README section changes. Never invent features, numbers or claims; link proof (tx, report, file) where you can. No en or em dashes. MDX: `{`, `}` and `<` outside code are JSX, keep them in backticks.
- **`docs.json`** is the whole configuration: theme, Stone & Lime colors (primary `#3E5C00`, lime `#D8F04A` in dark mode), logo (`logo/`, copied from `design/logo/`), favicon, navbar (Trust, Status, GitHub) and navigation. A new page must be added to `navigation` or it does not show in the sidebar.
- **API reference:** the **Endpoints** tab is generated by Mintlify from `docs/openapi.json` on `main`, referenced by its raw GitHub URL. Mintlify refuses paths outside this folder (`../` is not allowed), and a copy here would drift from the one source the backend maintains. So an endpoint change shows on the site once it is on `main` and Mintlify rebuilds (any push that changes `apps/docs`, or a manual redeploy in the dashboard). Each endpoint has a playground that calls `servers` from the spec (the hosted API). `api-reference.mdx` is the prose page in the sidebar.
- **For agents, from Mintlify itself:** `/llms.txt`, `/llms-full.txt`, every page as Markdown at `<page>.md`, `/skill.md` and a search MCP server at `/mcp`. Nothing to maintain here.
- **Deploys:** Mintlify's GitHub app watches `main`. Git settings in the Mintlify dashboard: repository `Hellonear-AI/hellonear`, branch `main`, "docs.json is in a subdirectory" on, path `/apps/docs`. Custom domain `docs.hellonear.xyz` is set in Mintlify's Domain setup; its `CNAME` in the `hellonear.xyz` Cloudflare zone (DNS only) is on the box owner's side (James), with Axel's approval. Pull requests get a Mintlify preview if the GitHub app is allowed to comment.
- The public repo `Hellonear-AI/docs` is Mintlify's onboarding starter, not used.
- **Our own look (Ancung, 13 Nov):** `style.css` (Mintlify loads every `.css` in this folder) gives the docs the web app's quiet scrollbars and the diagrams' colours, light and dark (`html.dark`).
- **Diagrams:** "How it works" draws its two diagrams in SVG from `snippets/how-it-works.jsx` (`Architecture`, `PaymentSteps`), not Mermaid, which shrank to unreadable text. Rounded nodes and curved, labelled links like the app's Mind Graph, dots travelling along them (hidden for reduced motion); HelloNear's own parts tinted lime, outside services plain. Desktop flows left to right; under 768 px the architecture is redrawn top to bottom and the payment becomes a step list, so text keeps its size. They show the same parts and steps the Mermaid diagrams did; change them together with the README. Mintlify's dev server doesn't reload a changed snippet: restart it.
- **Logos:** the Tech stack table shows each technology's logo left of its name (a fixed-width box and a hanging indent, so every name lines up; above the name on phones), where the README has one (copies in `images/brands/` from `design/brands/` and `docs/readme/brands/`; Mintlify can't read outside this folder). The README keeps them in a column of their own, which here was mostly empty. Dark mode swaps in the white versions (`hn-on-light` / `hn-on-dark` in `style.css`); NEAR AI has no white file, so its black mark is inverted.
- **Icons:** The agent's skill table and Connectors' app table show each item's icon left of its name, the README's own (`images/skills/`, `images/apps/`, copied from `docs/readme/icons/`), in a narrow 24 px box (`hn-icons`), kept on the left on phones. Two-column label and value tables have no column titles, so their empty header row is hidden (`style.css`).
- **Tab titles:** `title.js` (Mintlify loads every `.js` here) turns Mintlify's "Page - HelloNear" into "Page | HelloNear", like the web app's (docs.json has no separator setting). Only the tab changes; the server-sent title (search engines, link previews) stays Mintlify's.
- **Search** works on the deployed site only; `mint dev` asks for `mint login` (Axel's Mintlify account) to search locally.

## Commands

The Mintlify CLI is run with `bunx` at a pinned version (it needs Node 20.17+ and does not run on Node 25):

```sh
bunx mint@4.2.1184 dev --no-open --port 3333   # http://localhost:3333
bunx mint@4.2.1184 validate
bunx mint@4.2.1184 broken-links --check-anchors
```

Never run `mint signup`, `mint deploy` or `mint claim`: the project already exists and deploys from Git. CI: `.github/workflows/docs.yml` runs `validate` and `broken-links --check-anchors`.
